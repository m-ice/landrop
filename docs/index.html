使用说明

怎样在 GitHub Pages 使用？

将此 index.html 上传到仓库的 Pages 发布目录，在仓库 Settings → Pages 中选择发布分支。打开发布后的 HTTPS 地址即可使用，不要运行旧版 server.js。

怎样互传？

两端打开网页，一方输入对方的配对码或打开邀请链接，另一方确认连接。选择已连接设备与文件，点击发送。对方确认接收后开始传输。双方都可以发文件。

手机怎样一次选择多个文件？

点击“多选文件”选择任意格式，或点击“照片 / 视频”从相册选择多项。文件选择器中可尝试长按文件、点“选择 / 多选”，勾选后再确认。页面会将系统返回的全部文件加入队列，并显示本次数量；继续选择会追加，不覆盖之前的文件。选择器界面由浏览器和系统控制，内置浏览器只提供单选时，请改用系统浏览器。网页不能强制不支持多选的选择器返回多个文件。

大文件怎么保存？

支持“选择位置接收”的浏览器可边接收边写入磁盘，不设应用层文件大小上限，仍受磁盘、浏览器及网络条件限制。其他浏览器采用内存接收，本页文件数据总预算 256 MiB，实际内存占用更高且可能更早耗尽，收到后须点击下载。超出预算请分卷压缩，或换用支持直接保存的浏览器。

v3.1 传输优化

双方刷新到 v3.1 后，以 1 MiB 读取和合并写入；网络帧保持约 16 KiB，并通过发送缓冲事件和接收确认推进传输。与旧版配对时自动兼容。连接 / 速度诊断显示链路、延迟、读写次数和等待时间。优化不保证固定速度；不要关闭校验或无限扩大缓存。

离线与隐私

自动配对需要能访问公共信令服务，它会获知配对 ID、连接协商信息和连接 IP，但文件正文通过加密数据通道传输，不上传到 GitHub。网页加载后可通过手动交换连接信息，在允许设备互访的局域网内尝试不依赖外部服务的直连。手动模式不是绕过防火墙。

为什么连接失败？

先确认双方没有关闭网页、配对码填写正确。信令不可达时尝试手动连接。连接协商失败时，检查访客 Wi-Fi / AP 隔离、VPN 和防火墙；跨网络可能需要可用的 TURN 服务。手机请保持浏览器前台且屏幕亮着。

边界与安全

不会自动扫描整个局域网。文件夹先压缩，不限制文件后缀但浏览器或安全软件仍可能阻止某些下载。不打开或执行收到的文件；不要接受陌生连接。重要文件可通过另一个可信渠道核对双方显示的连接校验码。刷新、关闭页面或断线后不支持续传；需重新发送。未点击下载的内存文件会在关闭页面后丢失。
