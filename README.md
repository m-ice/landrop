# 邻传 · LAN Drop

一个可以实际运行的中文局域网文件传输网页。前端是完整的单文件 `index.html`，后端是使用 Node.js 内置模块编写的 `server.js`，不需要 npm install，不依赖 CDN、外部字体或云端接口。

## 最快开始

先在一台电脑上安装 Node.js 22 或 24 LTS（建议使用对应分支的最新维护版本）。把本文件夹解压到可写目录，不要直接在 ZIP 内运行。在该文件夹的终端执行：

```sh
node server.js
```

Windows 也可双击 `启动邻传.cmd`。macOS / Linux 可运行：

```sh
sh start.sh
```

控制台会打印类似下面的信息，实际 IP 和访问码以你自己的控制台为准：

```text
本机访问:  http://localhost:8080
局域网:    http://192.168.1.20:8080
访问码:    8 位随机数字
```

让其他电脑、手机或平板连接同一局域网，用浏览器打开**控制台给出的局域网 IP 地址**，输入访问码，即可加入。只有运行服务的电脑需要安装 Node.js，其他设备仅需浏览器。运行期间不需要外网。

请保持终端窗口和主机运行，不要休眠。防火墙有提示时，只允许可信的专用网络访问 TCP 8080；不要在路由器上设置公网端口转发。

## 如何发送

进入页面后，先选接收对象，再选择文件或把文件拖进页面，点击“开始发送”。接收方在“收到的文件”中点击“下载”，由浏览器处理保存。

- 选择指定设备：仅发送者和该接收设备能够通过接口访问文件。
- 选择“所有已加入设备”：文件向所有获得访问码的加入者共享，包括之后加入的人。此模式只能由发送者删除主机缓存。
- 指定接收设备离线时，不会自动切换成公开共享；页面会要求重新选择。

“已送达主机”表示上传已完整提交，并不表示对方已经下载，更不表示文件已经保存到对方磁盘。下载进度与最终结果请查看接收方浏览器的下载列表。

## 支持内容

不限制文件扩展名或 MIME 类型。可以发送图片、视频、音频、文档、压缩包、可执行文件、自定义后缀、没有后缀的文件、中文文件名、空文件等；传输的是原始字节，不转码、不压缩、不改变文件内容。为避免路径穿越和非法下载文件名，路径分隔符、控制字符及部分非法名称字符会被清理；过长的名称会截短。

文件夹本身不是文件，请先压缩成 ZIP 再发送。可执行文件等也可以上传，但接收方浏览器或操作系统仍可能进行安全拦截。程序不绕过这些限制，也不检查收到的文件是否安全。

页面包含批量队列、文件搜索、在线设备列表、设备重命名、进度与速度显示、同一页面内暂停/继续、分块重试、取消传输、删除缓存、中文提示、浅色/深色模式和响应式手机布局。

## 重要：这不是纯静态网站，也不是 P2P

```text
发送设备的浏览器
        │ 4 MiB 分块上传
        ▼
运行 server.js 的局域网电脑（临时磁盘缓存）
        │ 流式 HTTP 下载
        ▼
接收设备的浏览器
```

文件会经过并暂存于你运行服务的电脑，主机持有人能够接触这些文件。它们不会被本程序上传到外网；但这是**主机中转**，不是 WebRTC 点对点直传，也不是端到端加密服务。

单独双击 `index.html`，或使用 `python -m http.server`、VS Code Live Server 等普通静态服务器，只能打开页面，不能提供本程序所需的传输接口。必须使用配套的 `server.js`。

“附近设备”是已在同一个服务上通过访问码加入并持续轮询的浏览器会话，不是扫描局域网内所有设备。后台标签页和锁屏可能被浏览器节流，在线列表约 25 秒未收到活动就会暂时隐藏该设备。请保持移动端页面在前台。

## 文件大小与缓存

默认缓存**总配额为 20 GiB**，按所有任务声明的文件大小预留，既包含已完成文件，也包含未完成文件。单个文件不能超过总配额或当前剩余额度。可以用 `MAX_TOTAL_GB` 调大，实际仍受主机可用磁盘、文件系统单文件大小限制、接收设备空间、浏览器及网络条件约束。这里的 GB 配置按 1024³ 字节计算，即 GiB。

上传每个分块最多 4 MiB，后端使用流写入磁盘；下载使用文件流和浏览器原生下载，不在网页中把整个大文件拼成 Blob。支持单段 HTTP Range 请求、HEAD、ETag / If-Range；浏览器是否提供下载续传、以及是否保留下载任务，取决于具体浏览器。

暂停/继续和失败重试只覆盖**当前页面仍保留原 File 引用**的上传任务。刷新/关闭页面会丢失该引用，不提供跨刷新、跨重启的上传断点续传。页面刷新后，未完成缓存仍可在“发送记录”中删除，然后重新选择原文件发起新任务。清除浏览器 Cookie 或主机重启也会失去原设备身份；重新加入不会自动继承旧私有文件的接收权限。

默认在每个文件最后一个成功上传分块之后 **24 小时**自动过期；清理任务每分钟检查一次。暂停也计入这个时限，下载不延长时限。主机正常停止时删除本次运行的全部缓存；异常崩溃、强制结束、断电或直接关闭某些终端可能留下 `run-*` 临时目录，需要手动清理。历史目录会在下次启动时提示，不会被静默删除，也不会计入新进程的缓存配额。

每个进程最多保存 1000 个文件元数据任务，页面每个浏览器显示最近 250 个可访问任务；本地待发送队列最多 250 项。设备认证会话有效期为 48 小时，最多 128 个会话。

## 可选配置

所有配置均通过环境变量传入，无需修改源码：

| 变量 | 默认值 | 含义 |
| --- | --- | --- |
| `PORT` | `8080` | HTTP 端口，范围 1–65535 |
| `HOST` | `0.0.0.0` | 监听地址；`127.0.0.1` 仅本机可访问 |
| `ACCESS_CODE` | 启动时随机生成 8 位数字 | 可改成 8–128 个非空格 ASCII 字符 |
| `MAX_TOTAL_GB` | `20` | 本进程文件大小预留配额，单位 GiB |
| `TTL_HOURS` | `24` | 文件最后一次成功上传分块后的保留小时数 |
| `DATA_DIR` | 程序目录下 `.landrop-data` | 缓存根目录，程序在里面建立独立 `run-*` 子目录 |
| `ALLOWED_HOSTS` | 本机 IPv4 地址、localhost、127.0.0.1、[::1] | 额外允许的主机名，英文逗号分隔，不含协议和端口 |

Windows PowerShell 示例：

```powershell
$env:PORT="8080"
$env:ACCESS_CODE="Family-Share-2026"
$env:MAX_TOTAL_GB="100"
$env:DATA_DIR="D:\LanDropCache"
node server.js
```

macOS / Linux 示例：

```sh
PORT=8080 ACCESS_CODE='Family-Share-2026' MAX_TOTAL_GB=100 node server.js
```

示例访问码仅演示格式，实际使用请换成自己的随机访问码。

多网卡环境中，控制台和页面可能列出多个 IP，请使用与其他设备可达的那个。默认以 IPv4 访问为主；纯 IPv6 网络、反向代理和 HTTPS 没有作为开箱即用部署目标。自定义域名应加入 `ALLOWED_HOSTS`，且代理需保留正确的 Host；这不意味着已经配置好 TLS。

## 安全边界

本版本设计给可信家庭或办公局域网，**不应直接面向互联网部署，也不适合传敏感文件**。

HTTP 不加密访问码、会话 Cookie、文件名或文件内容，同一网络中的攻击者可能窃听或篡改。访问码不是替代 HTTPS 的安全机制，也不代表用户真实身份。程序没有账号体系、多因素认证、文件加密、恶意文件扫描或端到端内容校验。

已经实现的基础防护包括：随机访问码、按客户端 IP 限制连续错误尝试、随机 HttpOnly / SameSite 会话 Cookie、同源及 Host 检查、写接口自定义请求头、文件访问权限检查、随机缓存文件路径、名称清理、配额预留、分块大小及偏移检查，以及强制附件下载。文件名和设备名在前端作为文本渲染，不作为 HTML 执行。

## 常见问题

**另一台设备打不开地址。**
检查主机是否还在运行、IP 是否选对、设备是否真的在同一可互通网络，以及防火墙是否放行 TCP 8080。访客 Wi-Fi、AP 隔离、企业网络访问控制和 VPN 可能阻止互通。“同一个 Wi-Fi 名称”不一定保证互通。不要在另一台设备上访问 localhost，它只代表当前设备自身。

**页面出现，但传不了文件。**
确认使用的是 `node server.js` 输出的访问地址，不是普通静态服务器。前后端必须来自同一个服务和同一个 Origin。Cookie 以主机名为边界；在 localhost、某个 IP 和另一个 IP 间切换，会被当作不同站点会话。

**端口已被占用。**
停止之前的邻传服务或通过 `PORT` 换一个端口，例如 8088。所有设备都要使用新的端口。

**发送失败或缓存配额不足。**
检查主机实际剩余磁盘和写入权限，删除不需要的文件及未完成任务，或增大 `MAX_TOTAL_GB`。单纯调大配额不会增加实际磁盘空间。更改配置需要重启，重启前请让所有接收方先下载。

**下载以后，原文件会被删除吗？**
不会。程序从不删除发送设备上的原文件。“删除主机缓存”仅删除服务电脑上的临时副本，不会删除接收设备已保存的副本。

## 自动化测试

同一目录中运行：

```sh
node --test test.js
```

测试脚本自动启动一个独立的本机服务，使用随机空闲端口及独立临时目录，不修改你已经运行的服务。

包含 12 组接口测试：静态页面及认证校验、独立会话发现、9 MiB 多分块二进制上传及偏移检查、SHA-256 比对下载字节、第三方访问隔离、Range / HEAD / If-Range、空文件和文件名清理、共享和后来加入者、配额与分块大小限制、部分分块中断回滚及重传、主动取消、删除配额释放、访问码错误限流等。

开发环境中这 12 组测试已通过。还以离线浏览器 DOM 测试适配器连接本机接口，检查了页面事件、队列、定向发送、暂停继续、搜索、重命名、删除和 390/360 px 手机布局。该适配器不是浏览器原生网络路径；没有在真实手机、Safari、Firefox、Windows 和实际多机局域网中逐一实测，部署后请先用小文件完成一次本机网络验收。
